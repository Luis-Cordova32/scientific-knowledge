# Scientific Knowledge - Reference Guide

## Folder Structure

The `papers_folder` from `config.yaml` has this layout:

```
<papers_folder>/
├── references.bib              # BibTeX entries for all INGESTED papers
├── pending.bib                 # Optional: bulk BibTeX staging (SLR import), NOT ingested
├── papers-to-review.md         # Optional: batched ingestion queue w/ pre-assigned tag+topic
├── pdf/                        # Downloaded PDF files
│   ├── <tag>.pdf
│   └── ...
├── md/                         # Markdown conversions of PDFs
│   ├── <tag>.md
│   └── ...
├── synthesis/                  # Optional: cross-topic dated syntheses
│   ├── README.md               # Index of syntheses (newest supersedes older)
│   └── YYYY-MM-DD_<slug>.md    # Frontmatter: date, scope, counts, DB git commit
└── database/                   # Knowledge database
    ├── abstracts.json          # Index of all papers with metadata
    ├── citations.json          # Citation graph (auto-generated)
    ├── <topic>/                # Topic-specific folders
    │   ├── <tag>_summary.md
    │   ├── _synthesis.md        # Single-topic synthesis (regenerated on demand)
    │   └── ...
    └── ...
```

Only `references.bib`, `pdf/`, `md/`, and `database/` are created by the scripts. The
others (`synthesis/`) are human/agent
conventions layered on top and may or may not be present on a given machine — check
before assuming. `papers_folder` may itself be a git repo (see *Configuration* in
`SKILL.md`); if so, dated syntheses pin the commit they were built from.

## Database Schema

### abstracts.json

```json
{
  "papers": {
    "<tag>": {
      "title": "Full paper title",
      "authors": ["Author One", "Author Two"],
      "abstract": "Full abstract text...",
      "arxiv_id": "2301.12345",
      "url": "https://arxiv.org/abs/2301.12345",
      "published": "2023-01-30T18:00:00Z",
      "updated": "2023-02-15T10:00:00Z",
      "categories": ["cs.AI", "cs.LG"],
      "topic": "interpretability",
      "tag": "transformer-interp",
      "version": 1,
      "added_date": "2026-02-27T14:30:00"
    }
  }
}
```

**Local (non-ArXiv) papers** added via `process_local.py` use the same schema with
`arxiv_id: null` and these extra fields: `doi`, `journal`, `source: "local-pdf"`,
`bibtex_key`. `published`/`updated` hold the publication year, `version` is `null`,
and `categories` is `[]`.

### Summary File Format

Each `<tag>_summary.md` follows this template:

```markdown
# <Paper Title>
...
## My Notes
<!-- Preserved on regeneration. User's personal annotations go here. -->
```

### citations.json

Auto-generated by `citations` command or during `process`. Maps citation relationships.

```json
{
  "papers": {
    "<tag>": {
      "arxiv_id": "2301.12345",
      "title": "Paper title",
      "cites_in_database": [
        {"arxiv_id": "2210.54321", "tag": "other-paper"}
      ],
      "cites_external_count": 15,
      "cited_by": ["another-paper-tag"]
    }
  },
  "edges": [
    {"from": "<tag>", "to": "other-paper"}
  ]
}
```

```markdown
# <Paper Title>

**Authors:** <comma-separated authors>
**ArXiv ID:** <id>
**Date:** <published date>
**Version:** v<version>
**Topic:** <topic>
**Tag:** <tag>

## Key Findings
- ...

## Methods
- ...
- Datasets and scale

## Results
- Quantitative results with specific numbers
- Baseline comparisons (which baselines? strong/recent?)
- Statistical significance if reported

## Critical Assessment
- Overclaimed conclusions?
- Missing/weak baselines?
- Cherry-picked results?
- Reproducibility concerns?
- Scale and generalization limits?
- Statistical rigor (error bars, multiple runs)?
- Limitations acknowledged honestly?
- Potential confounds?

## Conclusions
- ...

## Relevance & Notes
- ...

## My Notes
<!-- Preserved on regeneration. User's personal annotations go here. -->
```

## Script CLI Reference

### arxiv_download.py

| Command | Description |
|---------|-------------|
| `fetch <arxiv_id>` | Fetch metadata and print as JSON to stdout |
| `process <arxiv_id> --tag <tag> --topic <topic>` | One-shot: fetch, download, store, convert. Reports cross-references. |
| `discover <query> [--max <n>]` | Search ArXiv, exclude papers already in DB |
| `search <pattern> [--field <field>]` | Search LOCAL database by regex. Fields: `tag`, `title`, `author`, `abstract`, `topic`, `all` (default) |
| `citations` | Rebuild citation graph from all stored markdowns |

All commands accept `--config <path>` to override the default config location.

The `<arxiv_id>` can be a bare ID (`2301.12345`) or a full URL (`https://arxiv.org/abs/2301.12345`).

### process_local.py (non-ArXiv PDFs)

| Command | Description |
|---------|-------------|
| `process <pdf_path> --bib <bibfile> [--tag <tag>] [--topic <topic>] [--engine <engine>]` | Ingest a LOCAL PDF using BibTeX metadata: copy PDF, append BibTeX, add a `arxiv_id: null` entry to `abstracts.json`, convert to markdown, rebuild citation graph. Prints JSON with `summary_target`. |

- `--bib -` reads BibTeX from stdin (pasted text); `--bibtext "<entry>"` passes it inline.
- Only `title` is required in the BibTeX; `abstract`, `author`, `doi`, `year`, `journal` are used if present.
- Output JSON mirrors `arxiv_download.py process` — write the summary to `files.summary_target` using the same template.

## Dependencies

Install all required packages:

```bash
pip install docopt pyyaml requests markitdown pypdf
```

| Package | Purpose |
|---------|---------|
| `docopt` | CLI argument parsing |
| `pyyaml` | Config file loading |
| `requests` | HTTP requests to ArXiv API and PDF download |
| `markitdown` | PDF → Markdown conversion (primary engine, by Microsoft) |
| `pypdf` | PDF → Markdown conversion (fallback, plain text extraction) |

## Topic Categories

Topics are flexible folder names under `database/`. New topics are created automatically
when you store a paper with a new `--topic` value. The set of topics (and how many
summaries each has) is entirely machine-specific — **always list `<papers_folder>/database/`
(or check `abstracts.json`) rather than trusting any list written down previously.**
Common examples seen across setups:

| Topic | Description |
|-------|-------------|
| `interpretability` | Mechanistic interpretability, explainability, circuits, probing |
| `sparse-autoencoders` | SAE architectures, pathologies, evaluation |
| `machine-learning` | General ML theory and method |
| `reinforcement-learning` | RL algorithms, reward shaping, RLHF |
| `language-models` | LLM architecture, training, evaluation |
| `computer-vision` | Image recognition, generation, segmentation |
| `general` | Default for uncategorized papers (`default_topic` in `config.yaml`) |

Prefer an existing topic close to the new paper's subject over creating a near-duplicate
one-off topic.
